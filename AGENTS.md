# Kita Chat: guide for coding agents

Kita Chat (package `com.nazchat.app`) is a bring-your-own-key AI chat app for Android.
It is a single-page web app running in an Android WebView, with native Java bridges.
Created by **Nazz**. © Nazz, all rights reserved (see LICENSE). Use the author name "Nazz" only.

## Layout

- `nazchat/`: the web app and the single source of truth for the UI.
  - `index.html`: shell, styles, core logic, Markdown renderer, providers, chat.
  - `studio.js`, `studio.css`: newer UI (sheets, settings, Chat|Code tabs).
  - `comfort.js`: reading preferences, Android Back handling (`kitaHandleBack`), the Kita picker that replaces native `<select>` dialogs.
  - Feature modules:
    - `provider-picker.js`, `integrations.js` (GitHub/Vercel/Cloudflare/Supabase), `agents.js` (orchestrator, agent team).
    - `websearch.js`, `network.js` (LAN tools), `pcap.js`, `webtest.js`.
  - `vendor/`: bundled libraries and fonts. There is no CDN at runtime.
- `nazchat-apk/`: the Android shell.
  - `AndroidManifest.xml`, `res/`.
  - `src/com/nazchat/app/*.java`: MainActivity and the `Naz*` bridges.
  - `assets/`: generated by `build.sh`. Never edit it by hand.
- `build.sh`: builds the APK with the plain Android SDK (no Gradle).
  - Asset allowlist: every new `nazchat/*.js` file must be added to the `for asset in …` line.
- `tests/`: Playwright (headless Chromium) browser tests (`*.test.js`) and host-JVM tests for native code (`native-*.test.cjs`).
  - `scripts/run-tests.cjs` lists every test file. Add new test files there.
- `version.json`, `NazChat.apk`, `RELEASE_NOTES.md`: release metadata and the signed APK.
  - The in-app updater reads `version.json` on `main` and the `<!-- kita-update … -->` marker in the latest GitHub Release.

## Setup

- Node.js 20 or newer: run `npm ci`.
- Chromium for the tests, either:
  - `npx playwright-core install --with-deps chromium`, or
  - set `CHROMIUM_PATH=/path/to/chromium`.
- JDK 17, needed for the native host tests and the APK build.
- Only to build an APK: Android SDK with `platforms;android-36` and `build-tools;36.0.0`, with `ANDROID_HOME` set:
  ```sh
  sdkmanager --sdk_root="$ANDROID_HOME" --install 'platforms;android-36' 'build-tools;36.0.0'
  ```

## Commands

- `npm test` runs the full suite: all browser tests plus native host tests.
  - It takes several minutes.
  - A file that fails is retried. Headless Chromium sometimes reads stale localStorage after a reload, so `studio`, `provider-delete` and `skill-editor-browser` may pass only on retry.
- `node tests/<name>.test.js` runs one browser test file.
- `UNSIGNED_ONLY=1 ./build.sh` checks that the APK builds. It needs no keystore.
- Open `nazchat/index.html` in a desktop browser for a quick look. The native bridges are absent there and the app falls back where it can.

## Rules

- **Never commit a keystore** (`*.keystore`, `*.jks`, `*.p12`), passwords, API keys or tokens.
  - Signing happens only in the GitHub workflow, from repository secrets.
- **Keep the signing identity.** Releases must be signed with the original key, certificate SHA-256 `ebd77288ed52773d694e35625e26e8ef8962eac0741e6b5eefc29f121dc598d3`. Otherwise phones cannot update over the installed app.
  - Keep the package id `com.nazchat.app`.
- **Never break stored data.** User data lives in localStorage (`nazchat_v1`), with a durable copy in NazStore.
  - Do not rewrite or delete stored conversations, providers or settings on upgrade.
  - Infer new fields when reading.
- **Security posture:**
  - API keys stay native (NazSecrets), bound to their origin.
  - Cleartext HTTP is off.
  - The network tools only touch the phone's own private subnet.
  - Generated HTML runs in PreviewActivity, which has no bridges.
  - Do not loosen any of these.
- **UI:**
  - Use the theme variables (`--bg2`, `--text`, `--border`, `--primary`, `--scrim`, …) so light and dark both work.
  - No native-looking dialogs; use the app's sheets and menus.
  - Phone first (390 px wide).
- **Tests:** every change ships with a test in `tests/`. Run `npm test` before you merge.

## Releasing a new version

1. Bump the version everywhere:
   - `nazchat-apk/AndroidManifest.xml`: `versionCode` +1 and `versionName`.
   - `nazchat/index.html`: `APP_VERSION` and `APP_VERSION_CODE`.
   - `package.json` and `package-lock.json`: two places.
2. Add a `# Kita Chat X.Y.Z` section at the top of `RELEASE_NOTES.md`, and the same notes at the top of `README.md`. Keep the "Created by" line directly under README's top heading.
3. Commit and merge to `main`. Do not touch `NazChat.apk` or `version.json`.
4. Run the **Build, sign and release** workflow on `main`: GitHub → Actions → Build, sign and release → Run workflow.
   - It runs the tests, builds, signs with the keystore from secrets, and checks the signer.
   - It then publishes the release and commits `NazChat.apk` and `version.json` back to `main`.

The older **Publish release** workflow publishes an APK that was already signed and committed by hand. It remains as a fallback.

Required repository secrets:
- `KITA_KEYSTORE_B64`: the keystore as one line of base64.
- `KITA_KEYSTORE_PASSWORD`.
- Optional: `KITA_KEY_PASSWORD` (defaults to the keystore password) and `KITA_KEY_ALIAS`.
