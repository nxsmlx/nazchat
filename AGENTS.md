# Kita Chat: guide for coding agents

Read this whole file before changing anything. It is the single briefing for any coding agent (OpenCode, Antigravity, Claude Code, Codex, Gemini CLI…) working on this repository.

Kita Chat (Android package `com.nazchat.app`) is a bring-your-own-key AI chat app.
- It is a single-page web app inside an Android WebView, with native Java "bridges".
- It is installed on real phones and updates in place from GitHub Releases.
- **Do not break people's installed app or their saved data.**

## 1. Requirements (install once)

| Tool | Version | Needed for | Check |
|---|---|---|---|
| Git | any recent | clone, commit, push | `git --version` |
| Node.js | 20 or newer (LTS) | tests | `node -v` |
| npm | comes with Node | installs `playwright-core` | `npm -v` |
| Chromium (via Playwright) | matching `playwright-core` | browser tests | `npx playwright-core --version` |
| JDK | 17 (Temurin recommended) | native host tests, APK build | `java -version` and `javac -version` |
| Android SDK | `platforms;android-36`, `build-tools;36.0.0` | **optional**: only to build an APK locally | `ls "$ANDROID_HOME/build-tools/36.0.0"` |
| `zip`, POSIX `sh` | any | `build.sh` | `zip -v` |
| GitHub access | `gh auth login`, or a git credential with push rights | push branches, open/merge PRs, run workflows | `gh auth status` |

You do **not** need a keystore, Gradle or Android Studio. Signing is done by GitHub Actions (section 7).

### Install, step by step

**Linux (Ubuntu/Debian)**
```sh
sudo apt-get install -y git zip openjdk-17-jdk
# Node 20+: https://nodejs.org or nvm
git clone https://github.com/nxsmlx/nazchat.git && cd nazchat
npm ci
npx playwright-core install --with-deps chromium
```

**macOS**
```sh
brew install git node openjdk@17
git clone https://github.com/nxsmlx/nazchat.git && cd nazchat
npm ci
npx playwright-core install chromium
```

**Windows**
- Install Git for Windows, Node.js 20 LTS and Temurin JDK 17.
- Use **Git Bash** or **WSL** for every command in this file. `build.sh` and the scripts are POSIX shell.
- Then run the same `git clone`, `npm ci` and `npx playwright-core install chromium` commands.

**If Chromium is already installed elsewhere**, point the tests at it: `export CHROMIUM_PATH=/path/to/chromium`.
- `tests/browser.js` also looks in `/usr/bin/chromium*`.

**Android SDK (optional, only for a local APK build)**
```sh
# Download "command line tools only" from developer.android.com/studio, unzip to $ANDROID_HOME/cmdline-tools/latest
export ANDROID_HOME=$HOME/android-sdk
yes | "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --sdk_root="$ANDROID_HOME" --licenses
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --sdk_root="$ANDROID_HOME" --install 'platforms;android-36' 'build-tools;36.0.0'
UNSIGNED_ONLY=1 ./build.sh     # must end with "Built unsigned, aligned APK"
```

### Check the setup works
```sh
npm test -- comfort                 # one quick browser test, a few seconds
npm test                            # the full suite (runs several files at once); ends with "All N test files passed in …"
```

## 2. Project layout

```

  studio.js / studio.css Newer UI: sheets, settings, Chat|Code tabs, keyboard/focus handling
  comfort.js             Reading preferences, Android Back (kitaHandleBack), Kita picker for every <select>
  design.js              Design kit: style presets + font pairings for Code builds, bundled Lucide icons (<i data-icon> → inline SVG)
  provider-picker.js     Provider preset dialog
  integrations.js        GitHub / Vercel / Cloudflare / Supabase publishing
  agents.js              Orchestrator, sub-agents, agent team (designer, tester, reviewer, fixer, database)
  websearch.js           Web search providers (Brave, Tavily, Exa, Serper, Search1API, built-in)
  network.js             LAN tools (own private subnet only), site audit
  webtest.js / pcap.js   Website test (verified domains), .pcap / .pcapng summary
  vendor/                Bundled libraries + fonts (marked, highlight, katex, pdf.js, mammoth). No CDN at runtime.
nazchat-apk/
  AndroidManifest.xml    versionCode / versionName live HERE
  src/com/nazchat/app/   MainActivity + native bridges (Naz*.java)
  res/                   icons, themes
  assets/                GENERATED by build.sh from nazchat/. Never edit by hand.
build.sh                 Plain-SDK build (javac → d8 → aapt2 → zip → zipalign → apksigner). No Gradle.
tests/                   *.test.js = Playwright browser tests; native-*.test.cjs = host-JVM tests of native logic
scripts/run-tests.cjs    List of every test file run by `npm test`
version.json             Update metadata read by the app from `main`
NazChat.apk              Latest signed APK (written by the release workflow; do not edit)
RELEASE_NOTES.md, README.md  Newest version on top
.github/workflows/       test.yml (every push), sign-release.yml (release), release.yml (old fallback), build-android.yml
```

Native bridges (registered in `MainActivity.java`, called from JS as `window.NazX.method()`):
- **Networking:** NazBridge, NazStream.
- **Secrets and storage:** NazSecrets (encrypted API keys), NazStore (durable copy of app state).
- **Sharing and files:** NazShare, NazClipboard, NazFiles.
- **Code and preview:** NazCodeCheck, NazPreview.
- **Accounts and connectors:** NazOAuth, NazMcp.
- **App shell:** NazUpdater, NazTheme, NazHaptics, NazVoice, NazWork (background builds).
- **Network:** NazDns (DNS-over-HTTPS), NazNetScan.

The web app must keep working in a desktop browser where these are absent. Check with `typeof window.NazX === 'object'` before using one.

## 3. Everyday workflow (do it in this order)

1. **Sync:** `git checkout main && git pull`.
2. **Branch:** `git checkout -b feature/short-name`.
3. **Read before editing.**
   - `grep -rn "functionName" nazchat/` to find where things live.
   - Most features span `index.html` plus one module.
4. **Change** the code in `nazchat/` (and `nazchat-apk/src/` only when native code is really needed).
5. **Add or update a test** in `tests/` for the change (section 5).
   - Add any new test file to the list in `scripts/run-tests.cjs`.
6. **Run only the related tests locally:** `npm test -- <names>`, e.g. `npm test -- network select-picker`.
   - The names are parts of test file names; this takes seconds.
   - Run the full `npm test` locally only when you changed shared core code: storage/`db`, streaming, `sendResponse`, the Markdown renderer or `studio.js` navigation. It runs several files at once.
   - Otherwise let CI run the full suite.
7. **Native or build changes:** if you changed Java, the manifest, `build.sh` or added a JS file, also run `UNSIGNED_ONLY=1 ./build.sh`.
8. **Commit and push:**
   - Write clear commit messages that say what changed and why.
   - `git push -u origin feature/short-name`.
9. **Open a pull request into `main`.**
   - CI (`test.yml`) runs the full suite on the PR in about 6 minutes.
   - Merge only when it is green. If it fails, read the log, fix and push again.
10. **Release** when the user asks for one (section 7).

Never merge into `main` with red CI. Never force-push `main`.

### Keep it fast
- One task means one branch and one PR. Do not stack unrelated changes.
- Do not run the full suite again and again. Run the related files while you work and let CI do the full run once.
- Do not poll CI every few seconds. Check about once a minute, or use `gh pr checks <n> --watch`.
- Commits are cheap. Commit as soon as the related tests pass; do not wait for a full local run first.
- Read only the files you need. `index.html` is large, so search it with `grep -n` and read around the hit instead of the whole file.

## 4. Rules: what to protect

### 4.1 Signing and identity (most important)
- **Never commit, print, log or upload a keystore** (`*.keystore`, `*.jks`, `*.p12`, base64 of one) or its passwords.
  - `.gitignore` already blocks these file types. Do not weaken it.
- Releases must be signed with the **original key**, certificate SHA-256 `ebd77288ed52773d694e35625e26e8ef8962eac0741e6b5eefc29f121dc598d3`.
  - A different key means phones cannot update; users would have to uninstall and lose their data.
  - Never generate a new keystore.
- Keep the package id `com.nazchat.app`, even though the app is called "Kita Chat".
- `versionCode` must always go **up** by at least 1 for every release.

### 4.2 User data
- App state is one JSON object `db` stored in `localStorage["nazchat_v1"]`, with a durable copy in NazStore. It holds conversations, providers, projects, settings and integrations.
- **Never rewrite, rename or delete stored fields on upgrade.** Add new fields with safe defaults and infer missing values when reading.
  - For example, `convMode()` infers the mode of old conversations and does not write it back.
- Reading must not create or modify state. An old bug made `integrationState()` write an empty object on read.
- Call `save()` only after a real user change.

### 4.3 Secrets and security
- API keys never live in JS state. They go to NazSecrets, and JS only holds a reference such as `provider:<id>`, `integration:github` or `search:brave#0`.
  - Native code adds the key to the request, and only for the host the key belongs to.
  - `NazSecretPolicy.java` decides which hosts that is. Do not widen it.
- Cleartext HTTP stays **off** (`usesCleartextTraffic=false`). Do not turn it on. For LAN banners the app uses raw sockets on purpose.
- Network tools only scan the phone's **own private subnet** and always ask first. Never add public-IP scanning, password guessing or exploits.
  - Active website tests run only on domains the user has verified.
- Generated or previewed HTML runs in `PreviewActivity` with **no** bridges. Never expose bridges to untrusted pages.
- No CDN or remote scripts. Bundle libraries in `nazchat/vendor/` and add their licences to `THIRD_PARTY_NOTICES.md`.
- Do not add analytics, tracking or any network call the user did not ask for.

### 4.4 UI
- **Phone first:** design and test at 390×844. Larger screens must still work.
- Use theme variables, never hard-coded colours:
  - Surfaces and text: `--bg`, `--bg2`, `--bg3`, `--panel`, `--text`, `--text2`, `--text3`, `--border`, `--hover`.
  - Accents and states: `--primary`, `--on-primary`, `--accent`, `--danger`, `--success`, `--warning`.
  - Overlays: `--scrim`, `--shadow-sheet`, `--safe-b`.
  - Check both the light and the dark theme.
- **No native-looking dialogs.** Use the app's own components:
  - `openSheet(id)` and `closeSheet(id)` for sheets.
  - `customDialog({...})` for confirm and prompt.
  - `toast(msg)` for short notices.
  - A plain `<select>` is fine; `comfort.js` automatically shows it as a Kita picker.
  - Never use `alert()`, `confirm()` or `prompt()`.
- **Android Back:**
  - A new overlay or menu must close on Back. Add a check in `window.kitaHandleBack` in `comfort.js`.
  - It must also close on Escape and on a tap on its scrim.
- **Accessibility:**
  - Give buttons and controls an `aria-label` or visible text.
  - Keep touch targets ≥ 44 px.
  - Keyboard focus must work.
- Keep wording short and plain. The UI text is English.

### 4.5 Code style
- Plain JavaScript, no framework and no build step. Small helpers already exist:
  - `$` is the query selector.
  - `el(tag, cls, html)` creates an element.
  - `esc(s)` escapes HTML.
  - `toast(msg)` shows a short notice.
- **Always escape** text before putting it in `innerHTML` (`esc()`), or use `textContent`.
- New JS file:
  - Put it in `nazchat/`.
  - Add a `<script>` tag in `index.html`.
  - **Add it to the asset list in `build.sh`** (`for asset in index.html studio.css …`). Otherwise the APK will not include it.
- Native code targets Java 8 bytecode. Android `minSdk` is 24 and `targetSdk` is 34.
  - Pure logic that can run without Android goes in a `*Core.java` class with a host-JVM test, like `NazDnsCore` and `NazScanCore`.
- Keep changes focused. Do not reformat or rename unrelated code.

## 5. Tests

- **Browser tests:** `tests/<name>.test.js`.
  - Each file launches headless Chromium on `nazchat/index.html` (via `tests/browser.js`), drives the real UI and asserts results.
  - Each prints `PASS …` and exits non-zero on failure.
- **Native tests:** `tests/native-*.test.cjs`. These compile the pure Java `*Core` classes and run them on the host JVM. Run them with `node --test tests/native-dns.test.cjs` and so on.
- **Full suite:** `npm test` (`scripts/run-tests.cjs`).
  - It retries a failing file up to twice. Files that pass only on retry are reported as FLAKY; a file that fails 3 times fails the run.
  - **Subset:** `npm test -- network comfort` runs only the files whose name contains one of the words.
  - **Parallel:** by default it runs up to 4 files at once locally (half the CPU cores) and 1 at a time on CI. Override with `npm test -- --jobs 2` or `TEST_JOBS=2`.

Writing a browser test:
- Start from a similar existing test, such as `tests/select-picker.test.js` or `tests/comfort.test.js`.
- Skip onboarding first: `await page.evaluate(()=>{db.onboardingDone=true;save();}); await page.goto(page.url());`.
- Block network to GitHub so the updater stays quiet: `page.route('https://api.github.com/**', r=>r.abort())`.
- Mock native bridges by assigning `window.NazX = {...}` in `page.evaluate`, and mock providers with `page.route` on their URLs. Never call real APIs or use real keys in tests.
- Use the 390×844 viewport.

Known pitfalls:
- **Stale storage after reload.** Headless Chromium can read stale `localStorage` after reloading a `file://` page. `studio`, `provider-delete` and `skill-editor-browser` sometimes pass only on retry. That is expected; a test that fails 3 times is a real failure.
- **Counts in older tests.** Some tests count rows in Hub and Tools. When you add a row there, update those counts (`ui-minimal`, `ui-460`) instead of deleting the assertions.
- **New agent roles.** Older tests opt out of extra roles with `db.agentTeam={designer:false,review:false}`. Keep new roles off by default in old tests the same way.
- **Selects in tests.** `page.selectOption()` still works on `<select>` elements; the Kita picker keeps the real `<select>` as the source of truth.
- **Never** skip, delete or weaken a test to make the suite green. Fix the cause.

## 6. Things to avoid (learned the hard way)

- Editing `nazchat-apk/assets/`: `build.sh` overwrites it. Edit `nazchat/` instead.
- Forgetting the `build.sh` asset list when adding a JS file. The app works in the browser, but the APK breaks.
- Migrations that rewrite old conversations or settings. Infer instead.
- Awaiting slow optional steps before a cancellable one. An old bug made Stop hang during web search. Cancel must always work quickly.
- Swallowing errors silently. Show them to the user (toast or inline row) and keep the app usable.
- Grouping every code block of an answer into tabs. Tabs are only for real multi-file answers (`isMultiFileAnswer`).
- Turning on cleartext, adding CDN scripts, logging secrets or widening `NazSecretPolicy`.
- Bumping `versionName` without `versionCode`, or the reverse. Also leaving `index.html`, `package.json` and the manifest out of sync. The release workflow refuses mismatches.
- Editing `NazChat.apk` or `version.json` by hand. The release workflow writes them.
- Committing large binaries other than `NazChat.apk`, or `node_modules/` and `test-results/`.

## 7. Releasing a new version (only when the user asks)

Version numbers: `MAJOR.MINOR.PATCH`.
- Fixes use PATCH, e.g. 4.15.2 → 4.15.3.
- Features use MINOR, e.g. 4.15.x → 4.16.0.
- `versionCode` always goes up by 1.

1. **Bump the version** in all of these, with the same numbers:
   - `nazchat-apk/AndroidManifest.xml`: `android:versionCode="N"` and `android:versionName="X.Y.Z"`.
   - `nazchat/index.html`: `const APP_VERSION = "X.Y.Z";` and `const APP_VERSION_CODE = N;`.
   - `package.json`: `"version"`.
   - `package-lock.json`: `"version"`, which appears twice near the top.
2. **Write release notes:**
   - Add a new section at the very top of `RELEASE_NOTES.md`, starting with the exact line `# Kita Chat X.Y.Z`, followed by plain bullet points (`- …`) of what changed for the user.
   - Put the most important change first; the first bullet becomes the in-app update summary.
   - End with `- VersionCode N, same com.nazchat.app package and original signing identity.`
3. **Update `README.md` the same way.** Its top is `# Kita Chat X.Y.Z`, then `Created by **Nazz**. © 2026 Nazz. All rights reserved; see LICENSE.`, then the new notes. Move the previous heading down.
4. **Test, commit and merge:** run `npm test`, then commit, push, open a PR and merge into `main` once CI is green.
5. **Run the release:**
   - Go to GitHub → **Actions** → **Build, sign and release** → **Run workflow** on `main`. Leave "dry run" unticked.
   - With the CLI: `gh workflow run sign-release.yml --ref main`.
   - The workflow:
     - reuses the green Tests run of that commit on `main`, or runs the tests if there is none;
     - checks that the version numbers match and are higher than the last release;
     - builds and signs with the keystore stored in repository secrets;
     - verifies the original signer;
     - commits `NazChat.apk` and `version.json` to `main`;
     - publishes the GitHub Release.
   - It takes about 7–15 minutes.
6. **Verify:**
   - Check that https://github.com/nxsmlx/nazchat/releases/latest shows `vX.Y.Z` with `NazChat.apk`.
   - Phones will offer the update from Settings → About → Check for updates.
7. **If the workflow fails,** open the run log, fix the cause (usually a version mismatch or a missing notes heading) and run it again. A run that fails never publishes anything.

To only check that the signing secrets still work: run the workflow with **dry run** ticked. It builds and signs without tests, commit or release.

Repository secrets are already set up by the owner, so never ask for or print them:
- `KITA_KEYSTORE_B64`
- `KITA_KEYSTORE_PASSWORD`
- Optional: `KITA_KEY_PASSWORD` and `KITA_KEY_ALIAS`

Download link to share (always the newest APK): https://github.com/nxsmlx/nazchat/releases/latest/download/NazChat.apk

## 8. Before you say "done": checklist

- [ ] The change works in light and dark theme at 390 px wide.
- [ ] Back, Escape and scrim close any new overlay.
- [ ] No stored data is rewritten, and old data still loads.
- [ ] No secrets in code, logs or commits, and no new network calls the user did not ask for.
- [ ] Any new JS file is in the `build.sh` asset list.
- [ ] A test covers the change and is listed in `scripts/run-tests.cjs`.
- [ ] The related tests pass locally, and CI is green on the PR.
- [ ] For native or build changes, `UNSIGNED_ONLY=1 ./build.sh` succeeds.
- [ ] For a release, the version is bumped in all places, the notes are on top, and the workflow is green.
- [ ] You told the user what changed, what you tested, and anything you could not test (e.g. on a real phone).
